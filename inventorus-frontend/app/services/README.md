# Inventorus Frontend - API Services

This directory contains the services and utilities for connecting the React frontend to the Zig API backend.

## Services Overview

The application provides services for three main entities:
- **Components**: Electronic components with specifications
- **Vendors**: Component suppliers and manufacturers  
- **Types**: Component categories and types

## API Configuration

The API base URL is configured to `http://localhost:8080` in `services/api.ts`. Make sure your Zig API server is running on this port.

## Available Services

### Component Service (`componentService`)
```typescript
import { componentService } from './services';

// Get all components
const components = await componentService.getAllComponents();

// Get specific component
const component = await componentService.getComponent(id);

// Add new component
await componentService.addComponent({
  type_id: 1,
  value: "10K",
  quantity: 100,
  footprint: "0805",
  vendor_id: 1,
  description: "10K ohm resistor",
  vendor_part_number: "RC0805FR-0710KL",
  price: 50 // in cents
});

// Add multiple components
await componentService.addManyComponents([...components]);
```

### Vendor Service (`vendorService`)
```typescript
import { vendorService } from './services';

// Get all vendors
const vendors = await vendorService.getAllVendors();

// Get specific vendor
const vendor = await vendorService.getVendor(id);

// Add new vendor
await vendorService.addVendor({
  name: "Digikey",
  description: "Electronic component distributor",
  url: "https://www.digikey.com"
});
```

### Type Service (`typeService`)
```typescript
import { typeService } from './services';

// Get all types
const types = await typeService.getAllTypes();

// Get specific type
const type = await typeService.getType(id);

// Add new type
await typeService.addType({
  name: "Resistor",
  description: "Passive electrical component",
  unit: "Ohm"

```

## Using the Custom Hooks

### useApi Hook
For simple data fetching:

```typescript
import { useApi } from './hooks/useApi';
import { componentService } from './services';

function ComponentList() {
  const { data, loading, error, execute } = useApi(
    () => componentService.getAllComponents(),
    [] // initial data
  );

  useEffect(() => {
    execute(); // Load data
  }, []);

  if (loading) return <div>Loading...</div>;
  if (error) return <div>Error: {error}</div>;
  
  return (
    <div>
      {data?.map(component => (
        <div key={component.id}>{component.description}</div>
      ))}
    </div>
  );
}
```

### useApiMutation Hook
For creating/updating data:

```typescript
import { useApiMutation } from './hooks/useApi';
import { componentService } from './services';

function AddComponent() {
  const { mutate, loading, error } = useApiMutation(
    (data: ComponentInsert) => componentService.addComponent(data)
  );

  const handleSubmit = async (formData: ComponentInsert) => {
    try {
      await mutate(formData);
      // Success - component added
    } catch (error) {
      // Error handled by hook
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      {/* form fields */}
      <button disabled={loading}>
        {loading ? 'Adding...' : 'Add Component'}
      </button>
      {error && <div>Error: {error}</div>}
    </form>
  );
}
```

## Error Handling

All services use the `ApiError` class for consistent error handling:

```typescript
try {
  await componentService.getAllComponents();
} catch (error) {
  if (error instanceof ApiError) {
    console.log('API Error:', error.message, 'Status:', error.status);
  } else {
    console.log('Unexpected error:', error);
  }
}
```

## Type Definitions

All TypeScript interfaces are available in `services/types.ts`:

- `Component` / `ComponentInsert`
- `Vendor` / `VendorInsert`  
- `Type` / `TypeInsert`
- `ApiResponse<T>`

## Development Notes

1. The Zig API expects prices in cents (integer), not dollars
2. All `*Insert` types exclude the `id` field (auto-generated by database)
3. The API uses standard HTTP status codes
4. CORS should be configured on the Zig server for development
